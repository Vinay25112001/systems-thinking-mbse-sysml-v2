# Week 1 Acceptance Matrix

Maintained under directive §22 (`docs/directives/2026-10-21_MASTER_IMPLEMENTATION_DIRECTIVE_WEEK1.md`). Created
2026-10-21 at Milestone M1. Every acceptance criterion from the proposal §14
(`docs/directives/2026-10-21_WEEK1_REDESIGN_PROPOSAL.md`), the directive §19 demonstrations A–E and the §20 academic
quality gate maps to requirement IDs in `docs/week1/spec/WEEK1_DESIGN_SPECIFICATION.md`, a milestone, a test type and the
test location to be created.

**Status rule (§24, independent QA §1).** A row moves to PASSED only when its named test exists, has run on the current
tree and passed, with the run recorded in `TEST_REPORT.md`. Manual faculty review rows move to PASSED only on a recorded
faculty sign-off. Earlier test claims are not evidence for the current tree (§4).

**Test types.** *Unit*: Vitest, jsdom project (`learning-studio/src/**`). *Integration*: Vitest, node project against the
local server with a temporary database (`learning-studio/server/**/*.test.ts`, backend doc §6). *E2E*: Playwright with
`playwright.server.config.ts`, two genuinely separate browser contexts where two roles are involved
(`learning-studio/e2e-server/`); the existing `learning-studio/e2e/` suites keep covering the static edition. *Manual
faculty review*: a recorded review against a checklist in `docs/week1/review/`.

**Status values.** NOT STARTED · IN PROGRESS · PASSED · FAILED · VERIFIED (verified before this matrix existed; evidence
cited).
