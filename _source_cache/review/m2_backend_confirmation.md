## Residual risks

- **What counts as material is a faculty decision.** `domain`, `suitability` and `soi` are shown to the instructor in `proposalOf` (`approvals.ts:38-42`) but are not material by default, so they can change after approval without re-review. That follows the stated FD default; faculty should confirm it.
- **Whitespace and type normalisation.** `text()` trims values and JSON-encodes non-strings, so whitespace-only edits never trigger re-review. That is intended.
- **Faculty notes share storage.** They are in their own table but in the same `sls.db` file and its backups. The separation is structural at the table and API level, not at the file level; D2 needs encrypted backups (this was already listed).
- **Scrypt denial of service in D2.** The shared 64-slot scrypt queue means sign-ins from rotating IPs can push everyone into 503 "busy". This needs a trusted-proxy setting and a shared limiter (already listed).
- **Snapshot churn.** Create/delete cycles are bounded by the 600 req/min session limit and the 50 MB per-project quota, and SQLite reuses freed pages. Proposal snapshots are outside the quota, but each one needs an instructor decision before the next request, so they cannot grow without bound.
- **The tsc failure in `src/week1/learn/dump.tmp.test.tsx`** belongs to another stream. It will break `npm run build` until it is removed.
